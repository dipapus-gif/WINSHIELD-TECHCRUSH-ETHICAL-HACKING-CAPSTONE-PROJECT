Documentation

Everything you need to use WinShield, in the order you will need it.

Quick start (browser edition)

  1. Open the browser edition in desktop Chrome or Edge.
  2. Click Choose a folder to protect. The browser asks for permission to view and edit that one folder. Other browsers can use Use a practice folder.
  3. On Folders and integrity, place decoy files and build a baseline while you know your files are clean.
  4. On Recovery, create a recovery point.
  5. Keep the tab open. WinShield re-reads the folder about every second and scores what changed.
After a reload the browser asks you to grant folder access again. Use the Reconnect button on the Folders tab.

Safe self-test

On the Dashboard, Run self-test creates 60 harmless text files in a WinShield-selftest folder inside your protected folder, plus a decoy. It then does what ransomware does, only to those files:

  • overwrites 14 files with random data (high entropy),
  • renames 22 files to .locked (extension change, ransomware extension),
  • modifies the decoy (honeypot),
  • creates HOW_TO_DECRYPT_YOUR_FILES.txt (ransom note).

The engine sees real file changes and raises a real Critical incident. Use Clean up self-test files afterwards.

Decoys and integrity

Decoy files

WinShield places three bait files in the protected folder and two in each of up to three sub-folders. Their names sort first and last so alphabetical encryptors hit one early. Any change to a decoy opens a Critical incident straight away.

Integrity baseline

A baseline stores the SHA-256 hash of every file up to 50 MB. Compare with baseline then lists each file that was modified, deleted, renamed (same content, new name) or added.

Recovery points

A recovery point copies your files into the browser's private storage. Identical content is stored once, so repeated points are cheap. Files over 25 MB are skipped and reported.

  • Verify selected re-hashes every stored file to detect damage or tampering.
  • Restore to a new sub-folder is the safest option because it changes nothing that exists.
  • Restore over originals replaces files that differ. Damaged versions are kept as evidence and every restored file is checked against its hash.

Points created while an incident is open are marked, because they may contain encrypted files. Prefer an earlier point.

If an alert fires

  1. Disconnect from Wi-Fi and unplug the network cable.
  2. Close the suspicious program in Task Manager, or shut the PC down.
  3. On the Incidents tab, save the evidence (JSON) and a report.
  4. Use Activate emergency protection to copy every file that has not been touched yet into a recovery point.
  5. Restore from a point taken before the incident and verify the result.
The browser edition cannot see or stop the program responsible. That needs the Windows app.

How scoring works

The engine looks at the last 10 seconds of events and counts distinct files, so one busy file cannot trigger an alert. Rules add points; the total is capped at 100.

SettingDefaultAllowed range
Window (seconds)103 to 120
Mass modify (files)405 to 5000
Mass rename, extension change (files)153 to 5000
Mass delete (files)405 to 5000
Ransomware-style extensions (files)31 to 100
High entropy (bits per byte)7.56.0 to 8.0
High-entropy file count82 to 1000

Severity bands: 35 or more is Medium, 60 or more is High, 85 or more is Critical. A touched decoy forces the score to at least 90. After the first alert, WinShield adds any rule that fires later (for example a decoy touched or a ransom note dropped) to the same incident.

Entropy is measured on the first 64 KB of a changed file. Files under 1 KB are skipped, and formats that are already compressed, such as photos, videos, PDFs and Office documents, are not counted.

A browser cannot be told about renames, so it infers them: a file that disappears and a file that appears in the same folder with the same name plus an extension, or the same size and timestamp, are treated as one rename.

Windows app

Requirements: Windows 10 or 11 and the .NET 8 SDK.

cd WinShield
dotnet run

Run it as administrator for the full feature set. Without administrator rights, monitoring, decoys, integrity checks, backups and alerts all work. Suspending some processes, Controlled Folder Access and network isolation need elevation.

Response modes

By default WinShield asks before any disruptive action. Settings let you choose automatic containment or automatic network isolation. WinShield never acts on core Windows processes, on itself, or on programs you marked as trusted.

Logic tests

cd tests\WinShield.Verify
dotnet run

The test project exits with code 0 when all checks pass. It does not cover the WPF screens.

Troubleshooting

Build error NETSDK1135

SupportedOSPlatformVersion 10.0.17763.0 cannot be higher than TargetPlatformVersion 7.0. This was a bug in an earlier project file. Use the latest source, or delete the SupportedOSPlatformVersion line from WinShield.csproj.

You only have a preview SDK (for example 11.0.100)

The project targets .NET 8. Install the .NET 8 SDK from Microsoft if the build or run step complains about a missing runtime or targeting pack.

A check says it could not run

Some checks read protected registry keys. Start the app as administrator.

The browser edition says folder access is unavailable

Use desktop Chrome or Edge over HTTPS. Other browsers can use the practice folder.

Monitoring seems slow in a background tab

Browsers throttle hidden tabs. Keep WinShield visible, for example in its own window, while you rely on it.

False alarms

Large builds, archive extraction and bulk photo exports can look like mass modification. Mark the incident as a false positive, and raise the thresholds in Settings if it keeps happening.

Privacy and limits

  • The browser edition makes no network requests after the page loads. Settings, incident history, baselines and recovery points stay in your browser's own storage for this site.
  • The page can only see the folders you grant. Clearing site data removes recovery points.
  • Detection is heuristic. WinShield is a defence-in-depth tool and does not replace Microsoft Defender or a tested backup on a separate drive or account.
  • Recovery points live in the same browser profile as the page. If ransomware can reach that profile folder, keep an external backup as well.
