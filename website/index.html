How it works

Four stages from the first suspicious file change to verified recovery.

Watch

Protected folders are scanned continuously. Each change becomes an event with its extension and a sample of the file's entropy.

Detect

Rules look at the last few seconds of activity: mass changes, extension swaps, ransomware-style names, near-random content and decoy touches.

Respond

An incident opens with severity, evidence and recommendations. The Windows app can also suspend the process, quarantine it and isolate the network.

Recover

Restore from a recovery point taken before the incident. Every restored file is checked against its hash, and damaged versions are kept as evidence.

Transparent detection

No black box. These are the rules and points the engine uses, with the default thresholds. All of them can be changed in Settings.

RuleFires when (defaults, in a 10 second window)Points
R-HONEYPOTA decoy file is modified, renamed or deleted60 (score at least 90)
R-MASS-MODIFY40 or more files created or modified (80 or more scores higher)25 or 35
R-EXT-CHANGE15 or more files had their extension changed30
R-SUSPICIOUS-EXTFiles appear with extensions such as .locked or .encrypted (3 or more scores higher)15 or 35
R-ENTROPY8 or more normally uncompressed files now hold near-random data (7.5 bits per byte or more)30
R-RANSOM-NOTEFiles named like HOW_TO_DECRYPT.txt are created (2 or more scores higher)25 or 35
R-MASS-DELETE40 or more files deleted20

Severity: 35 or more is Medium, 60 or more is High, 85 or more is Critical. Already-compressed formats such as photos, videos, PDFs and Office documents are not counted as high entropy.

The Windows app

A WPF desktop application on .NET 8 with a local SQLite database. It is built from source.

Build and run

Requires Windows 10 or 11 and the .NET 8 SDK. Run it as administrator to unlock process suspension, Controlled Folder Access and network isolation. The app offers a Restart as administrator button.

cd WinShield
dotnet run

Run the logic tests, which cover detection, integrity, backup and restore, reports and process safety rules:

cd tests\WinShield.Verify
dotnet run

Built to be safe to run

WinShield never acts on core Windows processes, on itself, or on programs you marked as trusted. Suspending a process, emergency protection and network isolation ask first unless you turn on the matching automatic option.

Quarantined files and damaged versions replaced during a restore are kept, not deleted. Everything is stored locally in %LocalAppData%\WinShield.

Test on a throwaway folder first. The app can suspend processes, quarantine files and cut off the network.

Questions

Straight answers, including the limits.

Does it replace antivirus or backups?

No. WinShield is a defence-in-depth tool. Keep Microsoft Defender on and keep a tested backup on a separate drive or account. Detection is heuristic, so expect occasional false alarms during large builds or archive extraction. You can mark those incidents as false positives.

Does anything leave my computer?

No. The browser edition has no analytics and makes no network requests after the page loads. Settings, history and recovery points stay in your browser's own storage. The Windows app stores its data in a local SQLite database.

Why can't the browser edition stop the program doing the damage?

Browsers deliberately cannot see other programs or control the operating system. The browser edition tells you what changed and gives you evidence and recovery points. To suspend a process or isolate the network you need the Windows app.

Which browsers can watch real folders?

Desktop Chrome and Edge, using the File System Access API. Other browsers can still use a practice folder kept in memory, which is useful for trying the self-test.

Will it keep watching if I close the tab?

No. Monitoring runs only while the page is open, and browsers slow background tabs. Keep the tab visible while you rely on it, or use the Windows app for continuous protection.

Is the self-test safe?

Yes. It creates 60 harmless files in a folder named WinShield-selftest, overwrites only those with random data, renames them to .locked, and touches a decoy it created. Nothing else is modified, and one button removes it all.

What if an alert fires for real?

Disconnect from the network first, close or shut down the suspicious program, save the evidence file, then restore from a recovery point taken before the incident and verify the files. Do not pay or contact the attacker before checking your backups.
